4. DATABASE SCHEMA
================================================================================

Table: liquidations
-------------------
- id INTEGER PRIMARY KEY
- timestamp INTEGER (ms since epoch)
- symbol TEXT (e.g., "SOL/USDT")
- side TEXT ("long" or "short")
- volume_usdt REAL (liquidation volume)
- liquidation_price REAL
- current_price REAL
- executed INTEGER (0 or 1)
- entry_price REAL (if executed)
- exit_price REAL (if executed)
- exit_reason TEXT ("Take Profit", "Stop Loss", etc.)
- pnl REAL (if executed)
- created_at INTEGER

Indexes:
- idx_liquidations_symbol (on symbol)
- idx_liquidations_timestamp (on timestamp)
- idx_liquidations_side (on side)

5. HOW THE OPTIMIZER WORKS
================================================================================

DATA COLLECTION:
1. Bot detects liquidation opportunity
2. Opportunity logged to database via /api/liquidations/log
3. Happens automatically in background

OPTIMIZATION PROCESS:
1. User clicks "Run Optimizer" button
2. Check if ≥50 liquidation events collected
3. For each symbol:
   a. Get historical liquidations from database
   b. Calculate volume percentiles (50th, 70th, 85th, 95th)
   c. Test 4 long thresholds × 4 short thresholds = 16 combinations
   d. For each combination, backtest:
      - Filter liquidations by threshold
      - Simulate trades (60% TP hit rate, 40% SL hit rate)
      - Calculate: PnL, win rate, max drawdown
      - Score = PnL - (maxDrawdown × 0.5)
   e. Pick best combination
4. Return recommendations for all symbols
5. User can apply suggestions

BACKTEST SIMULATION:
- Entry: current_price from liquidation event
- Side: Fade the liquidation (long liq = sell, short liq = buy)
- TP: entry × (1 ± tpPercent/100)
- SL: entry × (1 ± slPercent/100)
- Outcome: 60% hit TP, 40% hit SL (simplified for MVP)
- PnL: (price_change / entry) × size × leverage - fees
- Fees: 0.075% round-trip

7. HOW TO USE
================================================================================

STEP 1: COLLECT DATA
---------------------
1. Start the bot: npm run dev
2. Let it run for a few hours to collect liquidation events
3. Minimum 50 events needed (ideally 100+ for better accuracy)
4. More data = better optimization results

STEP 2: CHECK STATUS
--------------------
1. Click "Run Optimizer" button in UI
2. If insufficient data, you'll see:
   "Need X more liquidation events. Keep the bot running to collect data."
3. Status shows:
   - Total opportunities collected
   - Executed trades
   - Current performance stats

STEP 3: RUN OPTIMIZATION
-------------------------
1. Once you have 50+ events, click "Run Optimizer"
2. Optimizer analyzes all symbols
3. Shows results:
   - Current performance vs Optimized performance
   - Recommended threshold changes
   - Projected improvement in PnL

STEP 4: APPLY SUGGESTIONS
--------------------------
1. Review the recommendations per symbol
2. Click "Apply Suggestions" to update strategy
3. New thresholds are saved to config
4. Bot uses new settings immediately

STEP 5: ITERATE
----------------
1. Run bot with new settings for more time
2. Collect more data
3. Re-run optimizer to refine further
4. Repeat cycle for continuous improvement

11. DEBUGGING TIPS
================================================================================

CHECK DATABASE:
---------------
# Count opportunities
sqlite3 data/liquidations.db "SELECT COUNT(*) FROM liquidations"

# View recent liquidations
sqlite3 data/liquidations.db "SELECT * FROM liquidations ORDER BY timestamp DESC LIMIT 10"

# Check per-symbol counts
sqlite3 data/liquidations.db "SELECT symbol, side, COUNT(*) FROM liquidations GROUP BY symbol, side"

# See executed trades
sqlite3 data/liquidations.db "SELECT * FROM liquidations WHERE executed = 1"

CHECK OPTIMIZER LOGS:
---------------------
- Server console shows: "[Optimizer] Starting optimization for X symbols..."
- Browser console shows API calls
- Check for errors in optimizer.ts

COMMON ISSUES:
--------------
1. "Insufficient data" error
   → Need more liquidation events, let bot run longer

2. Optimizer returns empty results
   → Check if symbols have data: SELECT symbol, COUNT(*) FROM liquidations GROUP BY symbol

3. Database locked error
   → Close any open SQLite connections
   → Restart server

4. "Cannot find module 'better-sqlite3'"
   → Run: npm install better-sqlite3

5. Results don't make sense
   → Check backtest logic in optimizer.ts
   → Verify TP/SL calculations
   → Review win rate assumptions
